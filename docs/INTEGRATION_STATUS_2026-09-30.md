- The new authentication page probes a service-role-only marker installed by the last integrated migration. If the private server credential, database, or required schema is missing, email and Google submission fail closed and all six locales explain the temporary pause. The marker itself is read-only and grants no client access.
- The draft PR preview builds on Netlify. In the cloud browser, the Arabic and English desktop homepage, language switch, registration surface, and journal cards/source links rendered; the paused registration state was observed on the new preview. The Netlify Drawer error overlay is injected by Netlify, not by GazaWorks.
- Official Netlify project settings have `PAYMENT_PROVIDER=disabled` and `AI_PROVIDER=disabled` across contexts. The empty Gemini secret placeholder was removed. No bank payment, subscription, or paid AI plan was enabled.
- A private logical recovery archive was saved for the owner before schema changes. It contains the exact historical migration SQL, a live schema catalog, and 99 table snapshots; local checksums and counts passed. There were no storage objects. A restore on another Supabase project has not yet been exercised.
- Supabase project is on the Free plan. The five integrated migrations are now applied in production, bringing its migration history to 15 records. The existing Auth user and profile were preserved. `gw_provision_profile`, the private email outbox, and the service-role-only readiness marker exist; the `authenticated` role cannot call the marker.
- A later review found that CMS articles and pages could publish before their translations saved. Draft PR #7 now contains actor-bound, audited, transactional CMS RPCs and a database regression test. GitHub Quality run 172 passed the disposable PostgreSQL migration and failure rollback test, TypeScript, ESLint, 171 unit tests and Next.js build. The `atomic_cms_publication` migration was then applied to the connected project. Its existing one profile, nine pages and 26 page translations remained unchanged, and browser roles cannot execute the new publication RPCs. Signed-in editorial acceptance remains outstanding.

Automatic live headline intake has not yet been proven against a matching real feed item in production.

Only `EMAIL_PROVIDER=disabled` was independently visible after it was saved in the project UI. Browser sign-in was lost when its cloud session restarted, so no API key or sender configuration is claimed active.
