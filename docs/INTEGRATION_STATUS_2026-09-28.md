# GazaWorks integration checkpoint — 28 September 2026

This describes an integration worktree combining the visual preview with the security/workflow branch. It is **not** deployed or a launch approval. The existing Netlify preview contains only the visual branch.

## Implemented on the review branch

- Restored the existing GazaWorks-branded Gaza hero image and green logo; extended the light public theme, contrast, focus indicators, reduced-motion behavior, and responsive layout refinements. Fixed language-switcher query preservation after hydration, its pale text on a white header, and the dark registration panel.
- Added a bounded server-side RSS headline fetch from UN News and Al Jazeera. The headlines link directly to their original publisher, carry dates and source labels, and fall back to curated editorial items if feeds fail. The separate CMS articles continue to be authored and translated within GazaWorks. The Netlify preview fetched live headlines; browser inspection found an unrelated political article matched through its long description. Both Gaza and a work topic must now appear in the title, with regression tests. Headlines without source images use branded editorial art. The English feed text is currently not translated into the other five languages.
- Added a Brevo transactional-email adapter and a validated public contact endpoint with a fixed recipient, same-origin check, bot honeypot, and local per-instance rate limit. It fails closed unless the server has `BREVO_API_KEY`, `BREVO_SENDER_EMAIL`, and `CONTACT_RECIPIENT_EMAIL`. No production email has been sent or confirmed. Brevo account and sender activation may require verification.
- Added a Gemini OpenAI-compatible provider selected by `AI_PROVIDER=gemini`, `GEMINI_API_KEY`, and optionally `GEMINI_MODEL`; explicit consent is required before AI input/document transfer. Missing credentials produce an unavailable response. A browser login is not an API integration; no production Gemini output has been verified.
- Added a localized client payment panel tied to existing agreements, with an explicitly inactive Bank of Palestine gateway option. It collects no card data and performs no transaction. `PAYMENT_PROVIDER=mock` remains development-only. A real integration requires Bank of Palestine's technical contract, merchant approval, legal/banking decisions, webhook verification, reconciliation, refunds and production tests.
- CMS pages now select translations only for the requested locale. Localized fallback headings and descriptions exist for terms, privacy, payment, dispute, verification, community rules, and FAQs in all six languages. Policy pages clearly identify draft content and no longer show an irrelevant promotional card. Final legal text must be reviewed and published before launch.
- Integrated account-bound workflow routes, their three pending migrations, reviewed admin panels, document draft confirmation, appointment history, project/offer/dispute panels and disposable PostgreSQL test harness. The visual Google registration now passes the selected account type, session login is checked, OAuth callback destinations are restricted to application pages, and cross-origin browser API mutations are rejected. AI document import requires explicit consent server-side. Production payment simulation is disabled for both Netlify and Vercel production.
- Replaced the other branch's Resend provider with a Brevo outbox adapter, a guarded scheduled worker and an authenticated Brevo delivery-event endpoint. Brevo's 30-minute idempotency window uses the outbox UUID; ambiguous retries stop for manual review at 29 minutes. No live message has been sent. Email delivery and webhook handling remain disabled unless independently configured.

- No credentials were obtained from browser account pages and no new secrets were written to Netlify. The existing production environment lacks the Brevo and Gemini keys, `SUPABASE_SERVICE_ROLE_KEY`, and `CRON_SECRET` according to its environment-variable metadata. Production email, AI, and scheduled/administrative server workflows therefore cannot be claimed operational.
- The production Supabase project has migrations corresponding to 0001–0010 only. The integrated migrations for atomic project/payment transitions and email outbox are not applied. Their source-file versions differ from the production migration history. A disposable PostgreSQL pass and rehearsed in-place upgrade are required; do not imply code tests prove production database behavior.
- Integrated workspace panels replace raw JSON in many places, but much operational copy still falls back to English for Turkish, Spanish, French and German. Browser testing of signed-in individual, team, client and administrator journeys on the integrated branch is still outstanding.
- The owner authorized Netlify deployment and the free account produced [draft PR #6's preview](https://deploy-preview-6--gazaworks.netlify.app). Production still runs the older `main` branch. The preview has been inspected for the Arabic homepage, team registration and English locale selection; it is not signed-in or mobile acceptance. No live production sign-in verification of these changes has occurred.
- Per-instance rate limiting does not prevent distributed abuse. Before public launch, use durable abuse controls, verify document and portfolio handling, finish translations and accessibility checks, and test the production configuration against actual credentials and approved workflows.
